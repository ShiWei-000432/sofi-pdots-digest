# 私有 GitHub Actions 云端部署

公开仓库仅保存代码和不带凭据的部署模板。私有运行仓库只运行已核查的固定 commit，不能把 ChatGPT 登录放到公开仓库的 Actions 中。云端仅使用官方 Codex CLI 的 ChatGPT 登录，不设置 API key，不自动切换付费服务。

## 运行结构

`deploy/private-runtime.yml.example` 复制到私有仓库 `.github/workflows/weekly.yml`，替换 `REPLACE_WITH_REVIEWED_PUBLIC_COMMIT` 为完整提交 SHA。只允许 main 分支的手动和定时事件；不接收 PR 触发。固定 Actions SHA 和 Codex CLI 版本。一个串行并发组，禁止取消正在运行的任务。

北京时间周五09:00运行；每天09:17检查补跑。已完成时不分析论文、不发信。每期最多3次生成尝试，每次工作40分钟、整个任务50分钟封顶；耗尽后失败退出等待处理。免费额度与账号其他仓库共享，需在 GitHub Billing 确认 Actions 预算为禁止超额付费。不能仅凭本项目耗时保证账号不会产生费用。

## 凭据和持久状态

使用单独 CODEX_HOME 执行官方 `codex login`，用户在浏览器完成授权。不要复制正在桌面并行使用的认证文件。配置仓库 Secrets：

- `CLOUD_STATE_KEY`：Fernet 随机密钥，仅保存于 Secret 和用户本地受限目录。
- `CLOUD_BOOTSTRAP`：gzip 后 base64 的一次性引导包，包含独立 ChatGPT auth、SMTP配置、周报 TOML、已发送标识及真实测试证据。小于 GitHub Secret 大小限制；不得打印、提交、发到聊天。

`bootstrap` 只允许首次初始化，之后绝不覆盖刷新后的认证。认证、数据库和报告均以加密压缩包存于**私有草稿 Release 附件**，不进入 Git 历史、公开制品或 Actions 日志。草稿正文只保存当前附件ID和密文SHA256；每次写入后读回校验，再提交清单。保留最近8个加密快照。仅使用运行器短期 `GITHUB_TOKEN`，不要求个人长期 PAT。

Codex 每次调用后保存刷新后的 auth。SMTP DATA 前持久保存 sending 状态，服务器接受后保存 accepted；若中断，恢复后转 uncertain，禁止自动重发。密钥丢失、状态缺失或验证失败都停止；不会重新用旧引导包悄悄运行。

## 首次上线顺序

1. 创建私有仓库并添加两个 Secrets。
2. 部署固定 commit 的工作流；运行 `bootstrap`，确认加密读写通过。此时发信保持暂停。
3. 运行 `test`：使用引导包中真实检索过的一篇论文，由云端 Codex 重新生成并验证中文摘要，通过独立测试 outbox 向配置收件人发一封迁移测试邮件。测试不更新生产水位。
4. 云端测试 SMTP 接受后暂停本机 launchd，再运行 `activate`。确认下一次 `check` 恢复状态、无重复邮件。
5. 删除不再需要的引导 Secret 可缩小凭据面，但必须保留加密密钥。认证失效需要受控重置，不能清空生产发送状态。

## 操作

在私有仓库 Actions → Private SOFI weekly runtime → Run workflow 选择：

- `check` / `weekly`：检查是否到期；到期且启用时运行，已完成不重复。
- `pause`：持久关闭发信，仍允许检查状态。
- `activate`：测试通过后恢复发信。
- `test`：只进行一次迁移测试，已接受后重复执行不重复发邮件。

取消所有检查：在 GitHub Actions 禁用该工作流。恢复：重新启用，再运行 check。不要手动删除草稿 Release 或附件。运行失败以 Actions 红色结果为告警依据；GitHub 邮件通知取决于个人通知设置。桌面 Codex 巡检仅作为在线时的额外检查，不是云端定时依赖。当前云端自动化只执行固定代码，不会自主修改项目。

## 限制

GitHub 排队可能延迟或漏触发；每天补跑不是实时保证。免费额度耗尽、登录撤销、网络或 SMTP 故障仍会阻止完成。SMTP 接受不是确认进入收件箱。加密档案展开或密文超过100MiB会要求维护，避免无限增长。已开始 SMTP 但结果未知必须人工核对后恢复。

参考：[OpenAI 私有 CI 认证](https://learn.chatgpt.com/docs/auth/ci-cd-auth)、[GitHub Actions 计费](https://docs.github.com/en/billing/concepts/product-billing/github-actions)、[调度限制](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)。

### 手动完整运行

在私有运行仓库 Actions → Private SOFI weekly runtime → Run workflow 中选择 `manual`，立即重新检索、生成并发送尚未推送的论文，不受本周已发送限制。云端必须处于已激活状态。每个手动任务保留独立的运行标识、归档及最多三次尝试；重跑同一个已成功任务不会再次发信。`check` 和定时触发仍按原计划判断是否到期。来源不完整会在周报中披露；SMTP 接受并不证明收件箱已经收到。
